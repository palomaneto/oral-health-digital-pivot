# Contributing to Oral Health Digital Pivot Project 🦷📊

Thanks for taking an interest in this project!
Although this is a professional pivot, skill refinement through advice, active support and constructive criticisms are essential to me and always welcomed.
This document explains the process for contributing and the standards to follow.

## How to contribute
1. **Open an issue** first to discuss major changes or new features.
2. **Pick a good first issue** or create a new issue describing the work.
3. Create a branch from `main`:
   - `git checkout -b feature/<short-description>`

4. Make changes and commit with clear messages:
   - Format: `type(scope): short description`
   - Examples: `feat(data): add synthetic generator`, `fix(readme): correct typos`

5. Push branch and open a Pull Request:
   - `git push origin feature/<short-description>`
   - Open a PR, describe changes, link related issue.

## Branch & PR rules
- Branches: `feature/*`, `fix/*`, `chore/*`
- PR title to reference the issue and be descriptive.
- Add a short testing note in the PR description.

## Code style & files
- Python: follow PEP8. Add basic linting if desired.
- Notebooks: keep narrative cells short and add explanations.
- Data files: **please do not** commit real patient data. Use synthetic or anonymised data.

## Issues labeling
- `good first issue` - easy tasks for newcomers
- `data` - dataset work
- `dashboards` - dashboard-related work
- `documentation` - docs, case study, slides
  etc.

## Reviewer checklist
- Code is clear and documented
- Notebooks have explanations for each step
- No sensitive data committed
- Changes consistent with project goals

## Code of Conduct
Please be professional and respectful. This is for any good-will contributors willing to help in this learning / portfolio project.
